# 启动检查与故障处理

直接运行入口即可：

```bash
~/code/codex-continue-automation/codex-continue.sh
```

程序先检查环境和目标，不发送消息。必需条件通过、且至少一个置顶会话满足提交条件后，才询问预约时间。检查可能切换置顶会话以读取状态，结束后会尽力返回原会话；检查期间请勿切换窗口。

仅检查、不预约：

```bash
~/code/codex-continue-automation/codex-continue.sh --preflight
```

## 检查范围

| 项目 | 通过条件 | 未通过时怎么做 |
| --- | --- | --- |
| 操作系统 | macOS 14 或更新版本 | 升级 macOS；本工具不支持 Windows、Linux |
| 芯片与程序架构 | 按真实芯片选择 Intel x86_64 或 Apple Silicon ARM64 | 入口会尝试按正确架构重新构建 |
| Python | 可运行的 Python 3.9 或更新版本 | 安装或更新 Python；可先安装 Xcode Command Line Tools |
| 构建工具 | 需要重建时可找到 Swift 编译器 | 按提示运行 `xcode-select --install`，完成后重试 |
| 本地文件 | 日志目录可写；辅助程序签名、架构校验通过 | 检查目录权限；按提示重新构建 |
| 防空闲睡眠 | macOS `caffeinate` 可用 | 检查系统组件；不能依靠它保证合盖或锁屏可操作 |
| 辅助功能 | 当前启动链已获系统授权 | 在系统设置中开启实际终端或二进制权限；回到同一终端重试 |
| 执行互斥 | 没有其它实例正在操作界面 | 等其结束，避免同时执行 |
| 桌面状态 | 本机已登录、未锁屏的图形会话 | 解锁并登录本机；不要从不可交互的远程会话执行 |
| 应用与窗口 | 唯一目标应用进程，焦点窗口和辅助功能树可读 | 打开并登录包含 Codex 模式的应用，关闭遮挡菜单，保持前台 |
| 置顶列表 | 列表完整可读、不为空，会话标题唯一 | 展开侧边栏与置顶分组，先保存并置顶目标，处理重名 |
| 会话身份 | 窗口、工具栏、侧边栏标题一致 | 等加载完成，检查标题和当前窗口 |
| 草稿 | 输入框唯一、可用，内容去空白后恰好为「继续」 | 自行保留其它草稿后，写入「继续」，不要发送 |
| 发送状态 | 唯一可用发送按钮，无运行、停止或排队状态 | 等任务结束，检查登录、额度和界面提示 |
| 消息历史 | 可建立用户消息基线 | 等历史加载完成；仍失败则提供脱敏检查日志 |

## Intel、Apple Silicon 与 Rosetta

- **Intel Mac**：显示 Intel，并选择 x86_64 辅助程序。
- **Apple Silicon Mac**：显示 Apple Silicon（M 系列），选择 ARM64 辅助程序。
- **Apple Silicon 上的 Rosetta 终端**：识别到翻译状态后会明确提示，仍构建并启动 ARM64 辅助程序；不会仅因为终端报告 x86_64 就误认为是 Intel Mac。

辅助功能授权与启动终端有关。更换终端、移动或重新编译程序后，可能需要重新授权。两种芯片都需要这项权限。

Rosetta 判断参考 Apple 的[翻译环境说明](https://developer.apple.com/documentation/apple-silicon/about-the-rosetta-translation-environment)。架构逻辑测试与 ARM64 编译验证不能替代 Apple Silicon 真机运行验收。

## 可预约目标与不参与的会话

例如检查到四个置顶会话，其中一个已经写好「继续」、其它三个没有准备草稿：

```text
[不参与本次预约] 未准备草稿的会话
  原因：composer 草稿不是恰好为继续
  处理：在这个会话的输入框只写「继续」，不要发送……
[可预约] 已准备的会话
  目标身份、继续草稿、发送按钮、运行状态及消息历史校验通过。
[通过] 必需检查完成，可预约目标 1 个。只处理本次通过检查的目标，其它会话不参与。
请输入执行时间……
```

没有任何合格目标时不会询问时间，也不会建立预约。需要更多会话参与时，先准备好它们的草稿，再重新运行检查。

预约只记录本次检查通过的标题，触发时按这些标题限定目标。后来新增的置顶会话或后来才填好草稿的会话不参与本次预约。任一限定目标无法从可靠置顶列表确认时，触发阶段会拒绝整轮发送；其它状态也会逐个复检。

## 只读预约

`--schedule-inspect` 检查权限、桌面、应用和当前会话能否可靠读取，**不要求预填「继续」或发送按钮可用**。它不会发送消息，预约触发时只读取当时的当前焦点窗口。

## 输出与日志

终端直接显示「通过／未通过／可预约／不参与本次预约」、原因和处理方法；预约状态使用中文说明。原始启动输出保存在 `logs/preflight.log`，执行与预约仍分别写入 `logs/执行.jsonl` 和 `logs/预约.jsonl`。

日志可能包含会话标题和路径，分享前请脱敏。它们被 `.gitignore` 排除，不随源码上传。

## 检查的边界

检查能确认当前本机环境与界面条件，不能提前证明服务器将在预约时间接受消息，也不能保证届时额度、网络、权限、会话标题或桌面状态不变。历史额度提示可能在额度恢复后仍存在，因此不会仅凭旧提示判断当前是否可发送。触发时会重新验证，失败原因与提交结果会记录到日志；结果不确定时不重发。
