## 独立会话真实验收

1. 人工新建独立测试聊天，先完成一次普通对话，使聊天保存并可在侧边栏识别。
2. 设置唯一标题，例如 `自动继续独立验收`，在输入框写入 `继续`，不要发送。
3. 保持该会话在前台，运行只读检查：

   ```bash
   ./codex-continue.sh --test --current-only --expect-title '自动继续独立验收'
   ```

4. 只有识别通过后，再执行一次：

   ```bash
   ./codex-continue.sh --run-now --current-only --expect-title '自动继续独立验收'
   ```

5. 人工确认历史仅新增一条用户「继续」。如需终止生成，手动点击停止；完成后由操作者归档测试聊天。工具没有自动停止或关闭会话的功能。

若输出「结果不确定」，先查看历史，避免直接重跑。全新未保存的聊天缺少可靠侧边栏身份，当前会被拒绝。

## 折叠长消息导致历史基线失败的修复

2026-10-21，定位到用户长消息正文容器内存在「显示更多」按钮。旧解析器拒绝包含任何按钮的正文，导致基线为 -1，即使当前草稿为「继续」且发送按钮可用，也不会尝试发送。

- 修复已知展开／收起按钮的处理，按钮标签不计入正文；未知控件和隐藏正文歧义仍拒绝。
- `--test` 同步检查历史基线，避免只读预检通过而正式执行因同一基线问题跳过。
- 汇总分别记录尝试、已确认、不确定、跳过与预检通过数量；无合格目标返回 3，不确定返回 4。预约器保留并解释退出状态。
- 同一份真实 AX 快照回放，修复前为 -1，修复后为 0；真实目标新版只读预检通过，基线为 0，发送尝试为 0。
- Intel / ARM64 通用构建、24 项 Swift 检查、11 项 Python 测试通过。
- 原始会话快照仅保留于临时目录，不随仓库提交；公开回归测试采用合成的同结构消息。
- 本次没有向业务会话发送消息。界面中可见历史额度上限提示，当前服务端是否接受新消息未验证。
